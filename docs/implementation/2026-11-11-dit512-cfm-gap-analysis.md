# DiT512＋actor仍落后U形CFM＋actor的诊断

## Material Passport

- Origin Skill: academic-research-suite / experiment-agent
- Origin Mode: validate；有界推理干预及梯度测量
- Origin Date: 2026-11-11，Asia/Shanghai
- Verification Status: ANALYZED；原始推理、逐位一致性及参数不变核验通过，未完成各因素的独立重训因果分摊。
- Version Label: dit512_cfm_gap_v1

官方150场景/4,219窗口的Avg mIoU为DiT512 **18.2074%**、U形CFM＋actor **28.6739%**，差10.4665个百分点。本次只在既有8个固定tune场景和另8个预选train样本上诊断，不改变官方成绩、不重训或修改原检查点。下表均为**8个tune场景的原生E0已知区域指标**，不能当作新的官方全网格结果。

当前证据支持三个具体问题：DiT的actor→occupancy注入在损害本批样本的生成；速度场在生成起点和语义细节上仍欠佳；现有latent/多任务loss不能充分反映这种误差。预训练差异与较粗的patch表示是重要的解释候选，但尚未独立量化贡献。旧hidden256的硬性秩瓶颈已解除，不能继续将它当作当前512模型的根因。

## 1. actor→occupancy注入确实造成局部退化

保持权重、历史、动作、初噪、NFE10和评分完全相同，只将`occ_delta_projection`返回的注入增量乘以给定倍率；occupancy→actor通路继续计算。这比直接关闭整个joint分支更具体。

| 注入倍率 | DiT512 mIoU (%) | U形CFM mIoU (%) |
|---|---:|---:|
| 1：原模型 | 17.3353 | 29.1259 |
| 0.5 | 19.2051 | 29.0881 |
| 0 | 20.5856 | 28.9461 |

DiT移除该注入得到**+3.2503个百分点**；U形模型移除得到−0.1798个百分点。独立关闭整个双向交互的结果与注入倍率0的occupancy指标一致。倍率1输出与此前未插桩运行的latent逐位一致，干预后所有参数及buffer哈希保持不变。

该DiT注入的RMS平均约为对应occupancy特征RMS的19.33%，U形约14.61%；DiT在最后一次场评估达到约24.31%。这些数值只描述当前特征坐标，不是跨模型统一的扰动强度标尺，也不能单凭gate大小判断质量。

源码中actor与occupancy是全局双向cross-attention：DiT在第4/8个block之后，将1,200个occupancy token投影到128维，与48个actor token交互，再把增量投回512维。这里没有显式的actor位置到occupancy空间ROI的注入掩码。局部actor信息能够影响整张场景的token；当前干预证据说明这条注入路径对本模型有害，但没有证明某个空间门控方案一定更好，也不能将这3.25个百分点直接当作官方10.47个百分点差距的因果份额。

## 2. latent MSE与语义生成质量发生明显脱节

在同一批8个tune样本上，NFE10完整生成的latent MSE如下。

| 项目 | DiT512 | U形CFM |
|---|---:|---:|
| 生成latent相对GT的MSE | 0.0000774545 | 0.0000709684 |
| 原生E0 Avg mIoU (%) | 17.3353 | 29.1259 |
| 随机时间occupancy FM MSE | 0.0673474 | 0.0557294 |
| Actor XY误差均值（米，仅该样本集） | 0.5877 | 0.7569 |

生成latent MSE相差约9.1%，mIoU相差11.79个百分点。并且NFE10→40时，DiT的latent MSE上升到0.0000981469，mIoU反而上升到21.0957%；U形也出现MSE与mIoU不单调的现象。因此不能继续把latent MSE下降、总loss相近解释为语义预测达标。

进一步做**使用GT的离线诊断控制**：令`e=预测latent−GT latent`，只把DiT的误差整体缩放到U形误差相同的RMS，再解码`GT+缩放后的e`。DiT得到19.5651%，仍低于U形原始29.1259%。相同RMS的各向同性高斯误差加入GT后，DiT对应控制为65.1106%、U形为67.0678%，远高于各自真实预测。这表明当前模型误差具有对语义有害的结构，不能简单当作等方差残余白噪声。上述GT依赖控制都不能用于推理，也不是修复模型的成绩。

训练目标的源码解释了为何可能漏掉这种问题：`ReactFlow.training_loss`以occupancy速度MSE和actor速度MSE为基础；`ConsistencyLosses`增加actor框附近的几何Dice、静态相邻帧概率一致性和运动学约束。**目前没有对全部已知未来体素的直接语义CE或语义Dice重建项**。静态时间一致只能要求相邻帧相似，不能独自保证相同的语义是正确的；actor框局部约束也不是全场景语义监督。这是已确认的目标覆盖缺口，是否增加某种语义损失就能补足差距仍需受控重训。

## 3. 速度场本身有误差；增加NFE只能部分缓解

固定同一份GT、初噪及条件，在真实直线路径`x_t=(1−t)ε+t·10z_GT`上测量预测速度与该桥目标`10z_GT−ε`的MSE。GT只用于这项oracle诊断，不进入正常生成。

| 生成时间t | DiT512速度MSE | U形CFM速度MSE |
|---|---:|---:|
| 0 | 0.0301933 | 0.0101009 |
| 0.1 | 0.0087311 | 0.0078678 |
| 0.5 | 0.0241943 | 0.0203427 |
| 0.9 | 0.2458210 | 0.2022576 |
| 0.97 | 0.5959629 | 0.5048169 |
| 0.99 | 0.9569535 | 0.7686837 |

生成起点DiT误差约为U形的2.99倍。高t的桥目标仍包含随机噪声分量，接近1时目标不确定性增加，不能把表中高t MSE上升直接当作实现错误。

在oracle t=0.5，用一次速度预测得到端点`(x_t+(1−t)v)/10`并解码，DiT仅12.7292%，U形32.7405%；即使提供包含未来GT的中间态，DiT也未把语义结构还原好。因此差距并非全部来自多步自由生成中的积分累积。t=0.9端点分别48.5484%/53.6764%，同样只是oracle控制。

| 采样 | DiT512 mIoU (%) | U形CFM mIoU (%) | 两者差距（百分点） |
|---|---:|---:|---:|
| NFE10 | 17.3353 | 29.1259 | 11.7906 |
| NFE40 | 21.0957 | 32.1685 | 11.0728 |

增加计算能改善两者，仍没有消除差距。不能据本表声称更多NFE能替代学习更准确的场；也未用官方validation挑选新采样设置。

## 4. 预训练与表示结构差异是重要候选，不能假定只是容量不足

| 项目 | DiT512＋actor | U形CFM＋actor |
|---|---|---|
| 总参数 | 40,525,259 | 12,657,355 |
| 主干参数 | 39,632,784 | 11,830,416 |
| 主干初始化 | 从零初始化 | `occfm_history.ckpt`的204个主干键 |
| 初始主干LR | 1e−4 | 2e−5 |
| best/最终步数 | 84,000 / 100,000 | 52,000 / 72,000 |
| occupancy token交互分辨率 | 每帧10×10，patch5 | 中间层每帧25×25 |
| 细节通路 | patchify、8层固定分辨率全局Transformer、线性输出 | 卷积、多尺度、down/up与高分辨率skip |

U形原训练runner显式调用`freeze_trunk(frozen=False)`，因此其主干确实参与微调。其预训练权重身份为`1a9002f9a9ac74948dd69dd34277a867c98d3ac551087d554bd2732c8b26ac59`；DiT没有相应的occupancy主干预训练。当前比较同时改变了初始化和优化过程，不能独立归因于“U形优于标准DiT”。DiT参数更多，也没有证据将问题简单归结为模型太小。

当前latent网格覆盖80米、每轴50格；patch5 token覆盖约8×8米，400个数值虽通过满秩映射保留，但注意力交换以更粗的空间单元发生。按相邻latent坐标模5统计**预测误差的空间梯度能量**，DiT跨patch边界/块内均值=1.1599，U形=1.0156。该周期性误差与patch结构相符，支持进一步排查细节重建通路；它不是已量化的主因比例，也没有证明减小patch一定解决问题。

8个预选train样本上，DiT原生E0 mIoU=21.3741%，U形32.4483%。本批训练样本也存在约11.07个百分点差距，现有证据不支持只把问题解释为验证集分布或泛化退化；仍需完整train评估才能判断总体拟合情况。

## 5. 检验过但没有得到支持的解释

- **旧秩缺陷仍存在**：DiT输入512×400、输出400×512均秩400；条件数分别2.4756/2.7372，没有旧模型强制遗留144维初噪的硬约束。
- **VAE上限太低或选错VAE**：同一GT latent解码在本批样本达到93.6812%，两模型VAE一致。
- **完全没有使用历史**：将历史latent清零，DiT降至0.3249%、U形0.0237%，两者都依赖历史。清零属于输入分布干预，不能将分数变化直接当作历史特征质量的统一标尺。
- **仅仅选了错误checkpoint**：训练中同一固定tune探针best84,000为17.3323%，最终100,000为17.7525%，现有证据不足以把10个百分点官方差距归给这项选择。未对最终权重重新跑官方验证。
- **DiT独有的严重actor梯度冲突**：4个固定tune样本中，DiT actor FM与occupancy FM的主干梯度cosine均为小正值0.0042–0.0313；加权几何项有2/4负值。U形也存在冲突，几何项3/4为负，actor梯度相对occupancy的范数反而更大。因此不能把“actor loss过大/梯度冲突更严重”认作DiT特有根因。这个结果不否认已观测到的推理注入退化。
- **评测数据或评分口径不同**：正式评测已核对相同4,219窗口、18项协议、5,723份共享输入SHA和10个生成评分函数AST，GT计数与mask一致；本次沿用相同源码归档和固定cache样本。

## 6. 接下来最有价值的修复顺序

1. 先建立同一DiT的occupancy-only训练基线，再加入actor，配对固定噪声评测；把“主干没学好”和“交互引起退化”分开验证。现有推理时关交互不能替代重新训练的occupancy-only消融。
2. 将actor→occupancy注入作为首要实现排查对象：检查显式空间位置/ROI约束、门控、增量零初始化及分阶段开启。保留occupancy→actor的收益，并用完整tune生成mIoU验证静态场景是否被损坏。当前仅做诊断，不将倍率0或0.5直接作为新正式模型发布。
3. 检查全场景语义监督与目标权重：针对连续预测端点增加受mask约束的语义监督候选，分别记录静态/动态类生成IoU；比较与仅latent FM的受控结果。保持未来标签只在loss/scorer中使用。
4. 为标准DiT建立可比较的occupancy预训练或暖启动，再进行joint微调；或对U形从零与DiT从零做预算匹配实验。不能直接把U形参数映射进不兼容的标准DiT。
5. 在tune上预先固定NFE/生成质量选模协议，检查更细patch或局部细节通路的成本与收益；当前小集只用于定位，后续正式结论需要未见确认性测试。

## 7. 运行、异常和证据

本次没有创建optimizer、没有执行训练更新。主诊断、注入/误差控制及最终梯度诊断均由两个独立进程使用专用环境和两张A6000执行，最终退出0/0。推理运行使用原训练/评测的独立普通文件源码副本，不导入参考仓库；两种模型的参数/buffer前后哈希一致。

U形梯度脚本先出现两次诊断设置错误，均已保留日志与退出码：第一次未过滤不求导参数；第二次过滤后发现旧构造器默认冻结整个主干。最终按原训练runner先解除主干冻结、再保留固定位置编码冻结，重新执行两个模型，均成功；未将这两次失败归咎于原训练。DiT修正前后梯度结果一致。原检查点和官方结果保持不变。
