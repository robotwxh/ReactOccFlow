# 2026-11-07：标准 DiT 的维度修复与生成监控

> 2026-11-11 后续实测：512维实验已训练100,000步，best84,000 EMA完成官方150场景/4,219窗口评测，全网格Avg mIoU=18.2074%；hidden256为2.5755%，U形CFM＋actor为28.6739%。修复后质量恢复但仍有明显差距，不把全部变化归因于单一因素。见 [正式评测](2026-11-11-dit512-miou-evaluation.md)。下文工程短跑及启动记录按当时状态保留。

根据 [差异诊断](2026-11-07-dit-cfm-gap-analysis.md)，将标准 DiT 分支改为 **patch5 / hidden512 / depth8 / heads8**。每块仍是400个latent数值，12槽仍是1,200个token。输入为400→512，输出速度为512→400，不再存在宽度256所强制保留的144维初始噪声。actor仍为128维，在第4层后交换两次；occupancy交互增量通过512↔128投影。U形分支、RF目标、latent缩放、单套冻结VAE和未来标签边界保持原设计。

`StandardDiT`构造时要求 `hidden_size >= patch_size**2 * in_channels`；对本项目的直接线性patch速度场，窄于patch的配置会抛出明确错误。保留标准adaLN与输出头零初始化：初始化时输出秩0是正常状态，不能与训练后维度硬上限混淆。512仅解除该结构限制，不保证训练后的输出矩阵一直满秩，也不保证达到OccFM的mIoU。

修改范围为独立包、四份DiT配置、训练器、相关测试及当前方案/实施计划。旧256维检查点与冻结源码继续保留，必须通过对应历史源码回放；不能把其完整状态当成512维模型的恢复文件。旧官方mIoU **2.5755%** 与U形CFM **28.6739%**的结果不变。

训练器现在在完整tune验证时输出每项损失的全局有效元素均值、权重及加权贡献，并从固定tune场景自由生成，记录原生E0已知区域的标准mIoU、生成/目标latent矩及输出头秩。默认8场景、NFE10、固定身份噪声，选取索引为 `[0,277,577,884,1202,1517,1829,2145]`，不访问官方validation。小集指标不能替代官方全网格结果。probe精确保留Python/NumPy/Torch随机状态、各模块模式与梯度开关，rank0错误会广播到所有rank。best checkpoint目前仍按完整tune联合损失选取，便于与历史协议比较；小集生成指标用于暴露总loss掩盖的生成退化。
