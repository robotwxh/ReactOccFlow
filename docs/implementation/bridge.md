# Simulator bridge and controller contract (T14 scoped)

`reactoccflow.simulation.bridge` defines a versioned, JSON-only message boundary for a future two-process simulator adapter. Messages carry an episode ID, monotonically increasing sequence, finite timestamp, sensor bundle metadata, current ego state, navigation condition, and optional model candidate/world outputs. NumPy numeric arrays are converted to JSON lists after finite-value, rank, and element-count checks. Unknown fields, executable values, bytes, pickle-like object arrays, non-finite numbers, and oversized payloads fail closed. Keys that identify future labels or ground truth (`future_trajectory`, `ground_truth`, `gt`, `target`, and labels) are rejected recursively. Predicted world outputs may use names such as `future_world`; the rejection applies to future truth fields.

`BridgeReceiver` enforces one active episode, rejects old sequence numbers and timestamp regressions, and exposes an explicit `reset_episode` for a new episode. `ControlResponse` preserves model and configuration fingerprints, the requested deadline, control values, and an optional failure reason. `InMemoryTransport` is a typed CPU test fake; it is not an external server and does not import CARLA.

`reactoccflow.simulation.controller.Controller` accepts a selected observed-only plan, validates measured timestamps, interpolates XY at the requested elapsed time, and emits bounded `VehicleControl` values. Throttle and brake are mutually exclusive. Timeout, invalid/non-finite plan, no candidate, missing sensor, and stale episode conditions all return an explicit deceleration fallback (`throttle=0`, bounded brake) with the reason retained in `ControlResult.failure_reason`.

The two-process boundary is deliberately future-facing: a simulator process would provide current/past sensor and navigation observations, while the model/controller process would return a control response. Future simulator truth is never transmitted through this contract. These CPU tests validate schema, freshness, interpolation, bounds, and fallback behavior only; no CARLA process, Bench2Drive run, closed-loop rollout, or closed-loop metric is claimed.
