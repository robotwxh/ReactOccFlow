# Branch collection protocol (T8 scope)

`reactoccflow.simulation.branch_collection` defines a simulator-independent backend contract. A future CARLA adapter must reset a fixed origin and NPC seed for every action branch, provide finite current/past public history with explicit coordinate frame and semantic taxonomy metadata, and explicitly declare `npc_trajectory_mode: responsive` in reset metadata and `npc_control_mode: responsive` in result metadata. Missing, unknown, open-loop, frozen, and prerecorded declarations fail closed. The candidate reference must be present for the requested action; an unavailable stopping candidate is retained as a failed branch. The collector resets all pending actions in an origin/seed group before executing any branch. The first action reset establishes the only baseline; an invalid first reset invalidates the pending group, and later resets are compared against the fixed baseline. Mismatches are retained as failed branches.

Returned trajectories, timestamped occupancy labels/masks, collision labels, and tracking errors are evaluation targets. They are written as independent numeric NPZ files with the exact seven-array schema (`ego_trajectory`, `actor_trajectories`, `occupancy_labels`, `occupancy_masks`, `collision_events`, `tracking_error`, `timestamps`) alongside JSON status records containing exact branch identity, schema/settings binding, and SHA-256. Atomic writes and resume verification open the NPZ with pickle disabled, check keys/ranks/temporal lengths/shapes, and reject changed settings, swapped/tampered identity metadata, or corrupt payloads. Failure branches use a separate empty numeric marker payload. Failure, timeout, crash, invalid output, and reset mismatch remain in the corpus; complete means every expected status exists and is separate from successful count.

Origins are assigned to train/tune/calibration/evaluation with a stable SHA-256 bucket, so every action and seed for an origin shares one split. The ten-family catalog in `configs/branch_collection.yaml` records scenario requirements only: placements, CARLA integration, semantic conversion, controllers, inference bridges, and learned response metrics remain future work. Synthetic unit-test fixtures are not research evidence, and this protocol does not establish simulator reactivity from metadata.
