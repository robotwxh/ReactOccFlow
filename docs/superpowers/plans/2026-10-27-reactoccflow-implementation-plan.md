### 1.2 必须执行的独立性规则

1. `OccFM/`、`IR-WM/` 是只读参考目录，禁止修改其中的源码、配置、权重、数据、Git 状态及生成文件。
2. 开发每一项功能前，先搜索两个参考项目；已有实现时，先复制所需代码及其依赖闭包到本项目，再修改复制件。
3. 两个项目均没有对应功能时，才在本项目中新增实现，并记录检索结果与新增原因。
4. 复制范围限于当前功能需要的文件或函数；不整体搬运两个仓库，不复制 `.git`、缓存、旧环境或无关资源。
5. 禁止软链接、硬链接、引用参考项目的 editable install、`PYTHONPATH`、`sys.path` 注入、`.pth` 文件和配置继承。
6. 数据缓存、权重、统计文件和配置中不得保留需要访问参考目录的运行时路径。
7. 项目训练、推理、评估只能导入项目自有代码或已声明的第三方依赖。
8. 不实际删除或重命名参考仓库。通过隔离导出测试，证明它们不存在时项目仍能工作。
9. 来源记录和学术引用可以保留参考仓库名称、原始路径、网址及 commit；这些信息不参与运行时文件解析。
10. 保留复制代码原有版权与许可证声明。IR-WM 的 Apache-2.0 及其文件内上游声明一并保留；OccFM 本地未见明确许可证文件，记录该事实，公开发布派生代码前再核实授权范围。

## 三、模型、数据和评测接口设计

### 3.1 两条数据管线

**历史兼容基线管线**：原 OccFM 网格、时序、latent 缩放、动作条件及评价口径的复现已经完成，现按用户要求移除运行模型与入口，只保留结果和来源记录。其日志真实 ego 轨迹条件属于当时预测任务的已知条件，不能当作实际规划性能，也不能挪作新 DiT 的效果。

**研究管线**：统一将历史观测、未来 occupancy 和 actor 状态表达在当前自车坐标 `E0` 中，约定 x 向前、y 向左、z 向上，距离单位为米、时间单位为秒。

- 原始 occupancy 从所属帧到 `E0` 的转换使用传感器外参与 ego pose；未来真值 pose 仅用于构造训练标签。
- 生成场景和未来 ego 坐标之间的转换，推理时只能使用候选轨迹。
- 不能默认将 VAE latent 的二维 warp 等同于三维 occupancy 的精确刚体变换。研究缓存优先由变换后的 occupancy 重新编码生成。
- 相比原方案，主实验网格固定为 `[-40,40]×[-40,40]×[-1,5.4]`、0.4m；更改分辨率必须重新生成标签、缓存并单独报告。
- 保留 18 类编码；空体素和未知体素分别按数据定义处理，不混为同一类。

### 3.2 时间、张量与观测边界


| 字段                  | 主实验形状       | 说明                                                         |
| ----------------------- | ------------------ | -------------------------------------------------------------- |
| `history_latents`     | `[B,6,16,50,50]` | 为兼容主干保留 6 个历史槽，默认末 4 槽有效，其余由 mask 标明 |
| `history_mask`        | `[B,6]`          | 仅由已有观测决定                                             |
| `ego_state`           | `[B,4]`          | 当前速度、加速度、航向变化率、转向或曲率状态                 |
| `ego_candidate_xy`    | `[B,K,6,2]`      | 未来 0.5–3.0 秒的 6 个 waypoint                             |
| `actor_history`       | `[B,8,4,6]`      | 位置、航向正余弦、二维速度                                   |
| `actor_observed_mask` | `[B,8,4]`        | 当前及历史可观测性                                           |
| `actor_future`        | `[B,8,6,6]`      | 联合预测的位置、航向与速度                                   |
| `actor_target_mask`   | `[B,8,6]`        | 仅用于训练损失和评价                                         |
| `future_latents`      | `[B,6,16,50,50]` | 未来 occupancy latent                                        |

actor 仅按当前可见状态选取最近 8 个，使用距离与稳定 token 排序，不能通过未来轨迹或未来碰撞情况挑选。类别和尺寸取自当前观测；位置、航向及速度作为动态变量。原方案的 `D` 由 actor 动态状态及其差分得到，避免重复定义不一致的运动输出。

没有 actor、actor 消失、轨迹不足 3 秒时通过 mask 处理。当前未观测的新进入目标和第 9 个之后的目标仍需由 occupancy 分支覆盖，不能从风险计算中整体忽略。

### 3.4 ReactFlow 联合生成

- 先保持 occupancy-only CFM 可运行，再增加 actor motion 分支。
- occupancy 主干采用标准 DiT：latent patch=5、hidden=512、depth=8、heads=8；12 槽共形成 1,200 个固定分辨率 token，各层进行全局时空 self-attention，没有 U-Net 编解码与跨尺度跳连。
- actor 分支复用复制后的时间编码、Fourier 编码及注意力基础层；8 个 actor×6 个未来槽共形成 48 个 token，hidden=128，在两层、4 头交互模块中分别进行 masked actor self-attention 和 FFN。
- 第 4 个 DiT Block 后接入双向 cross-attention：actor 更新时 `Q=actor, K/V=occupancy`；occupancy 更新时 `Q=occupancy, K/V=actor`。两路从同一轮状态计算，再经门控残差更新。occupancy 先投影至 128 维，交互增量回投至 512 维后继续后 4 层 DiT；两组 token 不拼接做共同 self-attention。
- 单套 VAE 在离线阶段分别编码历史观测与未来监督标签。训练读取 latent 缓存，仅对预测端点运行冻结 decoder；patch 线性投影和 unpatchify 不属于第二次 VAE 编解码。actor 不经过 occupancy VAE。
- occupancy 与 actor 使用独立高斯初始噪声、共享生成流时间；物理未来时间与生成时间分开命名。
- 采用线性 source–target 插值及速度回归；每种模态分别做有效元素均值，再加权求和。
- actor 的未来存在性单独预测，不能将真值存在性 mask 输入推理过程。
- 先使用 scene-centric 主模型；scene-to-ego refinement 作为后续对照配置，不列为主要原创贡献。

初始总损失固定为：

```text
L = L_occ_fm
  + L_actor_fm
  + 0.1 * L_actor_existence
  + 0.1 * L_occ_actor_consistency
  + 0.05 * L_temporal_consistency
  + 0.01 * L_kinematics
```

其中 occupancy–actor 一致性只对已选且有效的 actor 空间支持区域施加，避免把全部动态 occupancy 错当作 8 个 actor 的并集。

**世界模型不得把所有危险未来强行训练为无碰撞。** 危险场景的真实分布需要保留；碰撞约束主要作用于候选自车计划选择。运动学损失按车辆、骑行者和行人分别处理。

### 3.5 PlanFlow 与候选轨迹

- 首版生成 6 个二维 waypoint 或位移，航向、速度和曲率由轨迹与当前状态推导，静止时沿用上一有效航向。
- 网络组件先从已复制的 FM、轨迹编码和规划组件中复用；缺少轨迹生成 head 时新增。
- 默认生成 `K=8` 条候选；增加一条显式减速停车候选用于失败处理，并单独计入候选总数和时延报告。
- nuScenes 阶段只使用日志中真实执行的 ego 轨迹监督，不给任意扰动候选配上原日志未来作为“反事实真值”。
- 闭环阶段可以使用导航路线和地图条件；路线来源必须是仿真器提供的任务导航，不是未来专家轨迹。

### 3.6 风险估计、校准和选择

- 默认每条候选采样 `M=8` 个未来世界，ODE 步数为 8；进行 4/8/16 步及不同 K、M 的消融。
- 碰撞事件统一定义为 3 秒内 ego 车体与生成的障碍 occupancy 或 actor 车体相交；车体尺寸、朝向、有效高度及坐标系必须一致。
- 碰撞判断使用车体面积而非仅用轨迹中心点；范围外位置标记为越界，不通过 clamp 伪装成边界内预测。
- 多次采样先得到平滑频率 `(collision_count+0.5)/(M+1)`，再在独立校准集上拟合 isotonic 校准器；无校准和 logistic 校准作为对照。
- 校准标签来自实际执行对应候选动作后的碰撞结果。真实日志中的几何相交评价另行标注，不当作反应式碰撞真值。
- 风险阈值在调参集上从 `0.05、0.10、0.20` 中选择，按碰撞率、完成度的固定排序准则选定；测试集上冻结阈值。
- 全部候选超阈值时选择最低预测风险的减速方案，同时记录 `no_feasible_candidate`，不宣称保证安全。
- M=8 对稀有风险的分辨能力有限；概率主实验额外报告 M=32，并对小概率区间注明样本支持。

### 3.7 点云感知与闭环边界

主结果不能把 ground-truth occupancy 或真实 actor box 当作传感器观测。

- 研究初期使用 GT occupancy/actor 的实验明确标为 oracle 表示实验。
- 实际前端从当前和过去 LiDAR 构建计数、高度、强度和观测可见性特征；复制并适配已有 occupancy encoder 组件，通过当前帧 occupancy 与冻结 VAE latent 蒸馏训练。
- 当前目标感知从 IR-WM 的检测、匹配和 bbox 代码中提取可复用组件，再新增轻量 BEV 检测 head 和基于观测的关联跟踪。
- 标签只用于感知训练和离线评测；部署时 actor 历史必须由前端和跟踪得到。
- 规划器至少按 2Hz 的仿真时间更新，底层控制按 20Hz 跟踪；实际运行耗时单独测量，未达实时时不宣称实时。
- CARLA 0.9.15 与模型环境分进程运行。若官方 Python API 需要旧版 Python，采用独立仿真环境及本机 socket 传输，避免让模型工程降级到旧 OpenMMLab 环境。
- 通信消息包含版本、episode ID、时间戳、序号、传感器数组和当前 ego 状态；禁止传输未来真值到推理进程。

- 建立固定候选库、无世界模型评分、occupancy-only 评分三种规划对照。

**任务 T11：实现多世界风险与校准。**

- 流式处理候选与世界样本，解码后及时汇总事件，不长期保留所有巨大 occupancy logits。
- 拟合并保存校准器、输入特征定义、训练划分及 K/M/NFE 等配置。
- 计算 Brier score、NLL、ECE、可靠性图、风险–覆盖率曲线及实际事件数量。
- 校准器、阈值和候选选择规则在最终测试前冻结。

**交付与验收**：能够输入单个场景，输出候选轨迹、多个未来世界、原始及校准风险、最终轨迹和选择原因；不依赖未来真值完成选择。

### 阶段 P6：实际点云前端，第 9–11 周

**任务 T12：当前 occupancy latent 感知。**

- 复制并适配 occupancy encoder，新增原始点云到 voxel/pillar 特征的输入层。
- 使用当前帧 occupancy 标签和冻结 VAE 的 latent 作为监督，生成历史 latent 队列。
- 对模拟点云的视野、线数、噪声和掉点进行适配。

**任务 T13：当前 actor 感知与跟踪。**

- 从 IR-WM 复制可复用检测与匹配组件，在本项目中接上点云 BEV 特征。
- 使用当前帧目标框监督轻量检测 head，再基于历史观测关联形成 actor 输入。
- 从 GT actor 输入逐步切换为预测 actor，单独报告感知误差造成的世界预测与规划下降。

**交付与验收**：关闭 GT occupancy 和 GT actor 输入后，项目仍能从传感器数据生成计划；oracle 与真实感知两类结果分开记录。

### 阶段 P7：CARLA/Bench2Drive 闭环，第 11–13 周

**任务 T14：闭环桥接和控制。**

- 独立仿真进程读取传感器和导航，模型进程预测计划，控制器执行并反馈下一时刻观测。
- CARLA actor 真值和未来状态只用于评价与数据采集，禁止经通信接口进入正式推理。
- 控制时按计划的有效时间插值；旧 episode 的预测直接丢弃。
- 超时、无有效候选、传感器缺失或模型输出非有限值时执行减速策略并记录失败原因。

**任务 T15：闭环评估。**

- 首先完成自建交互场景，再运行 Bench2Drive 的 Dev10 开发路线。
- 冻结适配器与模型后运行完整 220 路线，记录采用的评测工具版本和 sensor 配置。
- 失败、碰撞、超时和崩溃均保留结果，不能通过跳过失败路线改善统计。
- 相同观测、导航、感知、控制器和时间预算下比较各世界模型/风险配置。

**交付与验收**：从真实传感器输入到控制输出的完整闭环链路成立；评测输出可追溯到模型、配置、路线和随机种子。

### 阶段 P8：效率、完整消融与论文产物，第 13–16 周

**任务 T16：预算受控的加速。**

- 比较 ODE 4/8/16 步、候选数、世界样本数、分块大小和 CFG 计算量。
- 将计算拆分为感知、候选生成、世界采样、解码、风险和控制，报告均值、p95 时延及显存。
- 必须先验证 teacher 的世界预测与风险，再考虑少步蒸馏；蒸馏不能替代反应式和校准有效性实验。

**任务 T17：完成实验表和复现包。**

- 运行核心消融和 3 个训练随机种子，按 scene 或 route 进行置信区间统计。
- 生成主结果、消融、动作干预响应、校准和速度–质量曲线。
- 汇总未达成的指标或失败场景，不把计划中的预期增益写成已有结论。
- 运行最终隔离验收并整理 README、数据准备说明、来源说明及全部实验命令。

**交付与验收**：可由另一位工程师仅使用独立项目、声明的数据集和自有权重重新运行主要结果。

## 五、训练配置、测试矩阵与最终验收

### 5.1 默认训练配置

- VAE 首先冻结并加载已有权重；只有专门的 VAE 实验才训练压缩器。
- 训练先单卡小样本，再双卡 DDP；默认每卡 micro-batch=2、梯度累积=2，有效 batch=8。
- 标准 DiT 主干与 actor/interaction 分支初始学习率均为 `1e-4`。AdamW、weight decay=0.01、梯度裁剪=1.0、EMA=0.9999。原 U-Net 的初始化/微调入口已移除，不再属于当前训练配置。
- 使用 1,000 步 warmup 和 cosine decay；每 2,000 步评估，连续 10 次无调参集改进时停止该阶段训练。
- 正式训练前均运行 200 步 smoke test 与 32 个样本的过拟合测试。
- 随机种子固定为 2026、2027、2028；数据划分、训练噪声和推理采样分别使用独立随机数生成器。
- 原始 checkpoint 基线使用其原有评估配置，不能用新优化器设置替代原始数值基线。
- 显存不足时依次降低采样分块、micro-batch 并增加累积；保持有效 batch 和实验配置变更记录，不能静默更改 K、M、预测时长或网格。

### 5.3 论文实验矩阵

主实验固定数据划分、输入模态、预测时长、前端、控制器和候选数，至少包括：

1. 原始历史条件 OccFM 与未来轨迹条件 OccFM 的预测任务基线。
2. occupancy-only、occupancy/actor 并行、双向联合 FM。
3. 无 ego 条件、原始 trajectory embedding、候选条件 actor 反应模型。
4. 去掉 occupancy–actor、时序和运动学一致性约束。
5. 相同候选下的无风险筛选、未校准筛选和校准筛选。
6. oracle occupancy/actor 与实际点云感知两种输入设置。
7. 相同初始场景和种子下的自车动作干预响应。
8. ODE 步数、K、M 与端到端时延的权衡。
9. scene-centric 与 scene-to-ego refinement 对照。
10. 完整闭环驾驶及其失败场景分析。

世界模型报告 occupancy mIoU、动态类别 IoU、actor ADE/FDE、energy score；概率报告 Brier score、NLL、ECE、可靠性图及分桶样本数；规划报告碰撞、完成度、越界、TTC、舒适性和时延。数据或模态不一致的外部论文结果只能作为文献参考，不并入声称公平的同表比较。

### 5.4 完成标准与研究判断

**工程完成**：独立副本无需两个参考仓库即可加载自有资源、训练、推理、评价并运行闭环；所有复制来源可追踪；参考仓库未被修改。

**实验完成**：核心对照与消融均有实际日志，数据分割和校准无泄漏，失败路线没有被删除，指标可以由保存的预测与事件记录重算。

**论文主张成立需要的证据**：在相同候选与计算预算下，显式 occupancy–actor 耦合能更准确预测动作干预响应；校准能改善风险概率质量；这些变化能够带来闭环驾驶收益。三者分别验证，不能由其中一项的改善推断其余两项必然成立。

如果反应式增益、校准增益或闭环收益没有出现，项目仍交付全部工程和结果，但论文主张随证据收窄，不预设必须获得正结果。
